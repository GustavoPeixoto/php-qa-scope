# Proposal

## Why

Provide a reproducible contributor QA gate for installed Git pushes and direct manual validation of the clean checkout, retaining detailed native reports and Lefthook-owned concurrency.

The previous Git/manual implementation used an internal PHP supervisor inside the shared `php` service to cancel native QA. Its replacement uses one temporary container per check, so Docker controls the complete native workload and every container is fully removed after success, failure, or catchable interruption.

Previously, execution directories mixed native reports, job outcomes, and container creation diagnostics. This revision groups retained files by validation and purpose so contributors can find reports and lifecycle evidence consistently. Every generated evidence file remains retained after success, failure, and interruption; automatic cleanup of successful runs is outside this revision.

Add OpenSpec bulk validation to the same contributor gate so structurally invalid specifications and active change deltas cannot pass merely because PHP QA succeeds. OpenSpec is already pinned at `1.14.0` in dev; it runs as a supervised local dev process alongside the six existing temporary PHP-container checks.

A real manual run exposed a separate completion/capture defect: Fixer and PHPStan had empty captured stdout despite a zero Docker-client return, while direct Composer execution with output persisted inside PHP produced valid zero-error JSON and real exit zero. QA Scope was incorrectly accepted with empty text. A control command containing a two-second delay returned from Docker execution in about 0.744 seconds with only its initial output; the local control waited and retained both messages. This establishes an unreliable completion/output path without attributing the cause to a particular client, daemon, or agent tool. The gate must observe actual container completion, collect complete output before removal, and reject missing evidence.

## What Changes

- Install only `pre-push` with Lefthook and require that pushes execute from the Compose `dev` service. Commits have no hook-specific environment requirement.
- Support both installed Git invocation and direct `lefthook run pre-push`. Select the mode before Lefthook forwards stdin: the installed launcher scopes an explicit Git-invocation marker to its child, while direct execution validates the current clean checkout without reading Git records or contacting a remote. Both modes require dev and share the same seven-check pipeline.
- Install the official `lefthook@2.1.16` npm package through the dev image's existing Yarn after `corepack enable`, with installation-scoped `CI=1` to suppress npm-time hook installation and an exact version smoke check. Replace the custom architecture/download/checksum block; `setup-git-hooks` remains responsible for hook activation.
- Centralize the required `QA_HOOKS_SERVICE=dev` marker in `docker/dev/.env.example` and the ignored local `docker/dev/.env`, loaded by the existing Compose `env_file`. Remove the inline Compose declaration; preserve other local environment values and document migration of existing files.
- Run the complete configured scope of the six existing PHP commands: `composer qa-scope check`, `composer sniffer-check`, `composer fixer-check`, `composer md-check`, `composer stan-check`, and `composer test`, in individually owned temporary containers derived from the existing `php` runtime. Add validation ID `openspec` running `openspec validate --all --strict --no-interactive --json` directly in dev from the repository root, with unchanged PHP Composer/script/report arguments.
- Use a small Python coordinator for pre-flight, execution-directory allocation, invocation of a custom Lefthook `qa-checks` group, and final result consolidation. Lefthook runs the seven validation jobs in parallel and waits for all outcomes.
- Validate Git's pre-push update records before QA: reject multiple effective updates; skip QA for no updates and a single deletion; require the current source branch or a detached checkout at the transmitted tag's commit for a single content update; require a clean index/worktree for that content update.
- Store native JSON reports for Sniffer, Fixer, PHPMD, PHPStan, and OpenSpec bulk validation, JUnit XML for tests, and text for QA Scope under `results/{validation-id}/` with separate `execution.log` diagnostics. Preserve staged stdout and partial/invalid output. Validate each native format and require the expected QA Scope target statuses; empty text or arbitrary JSON/XML cannot prove success. Retain job outcomes in `jobs/{validation-id}.json`, container completion/collection/cleanup evidence and creation receipts under `containers/{validation-id}/`, scheduler output in `runner.log`, and root `summary.json` under each UTC `logs/prepush/YYYYMMDD-HHMMSS-mmm/` until manual cleanup.
- Consolidate every check result and reject the push on validation, report, completion-observation, output-collection, or execution failure, including OpenSpec local failures, a nonzero Lefthook result, or unconfirmed PHP-container cleanup. Require a verified terminal Docker state and genuine native code rather than a start/attach/client return. No check failure suppresses seven-result consolidation or current-run cleanup.
- Handle SIGINT/SIGTERM from entry through input, pre-flight subprocesses, allocation, validation, and final consolidation. Use bounded, repeat-signal-safe teardown of owned local processes and temporary containers, with one five-second graceful plus five-second forced-removal/verification deadline; preserve completed evidence and record interruption rather than success.
- Give each PHP check container a unique name, immutable Docker ID, and execution/check ownership labels. Separate creation, identity registration, non-attached startup, observed native completion, output collection, and explicit removal. Create without `--rm`; retain the owned container only until completion evidence and logs are collected, then confirm complete Docker absence on every success/failure/catchable-interruption path, including containers never started.
- Keep existing dev/php services, shared mounts/networks, images, and retained reports. Do not create persistent QA services, prune Docker globally, or remove another execution's resources. Missing or unreachable Docker cleanup is an explicit unsuccessful outcome, never a claim that containers were removed.
- Centralize contributor hook documentation in `conventions/git-hooks.md`, moving the hook-specific sections from `conventions/environment.md` and `conventions/git.md` and leaving concise references in those documents. Retain report formats and retention in `conventions/artifacts.md`.
- Document semantic rules requiring agents to explain hook failures and suggest remedies, then await a new explicit instruction before fixing, staging, or retrying.
- State that agents MUST NOT bypass repository hooks without explicit human authorization for the specific operation, before or after a failure. Authorization to commit, push, fix, or retry does not imply bypass authorization; cover `--no-verify`, `LEFTHOOK=0`, disabling hooks, and equivalent mechanisms.

### Scope Boundaries

Only pre-push is installed. No pre-commit gate, commit-environment enforcement, temporary hiding/restoration of local changes, index fingerprint protocol, pending-stash detection, interprocess lock, Python parallel scheduler, automatic fixes, automatic checkout changes, staged-filename filtering, report pruning, or new start/attach lifecycle checks are introduced. This is contributor automation, not a QA runner distributed by the PHP package.

Manual invocation performs all seven checks of the current clean checkout, including detached HEAD, without transmitting a reference or granting push authorization. Git mode retains its update/branch/tag/deletion policies and early returns. Lefthook owns scheduling; lifecycle supervision owns cancellation. The running php service remains the runtime template and dependency pre-flight target. Six PHP tools run directly in temporary containers, with Docker-managed init and no internal PHP/shell supervisor; OpenSpec remains a local dev process. Temporary containers may exist in exited state during bounded evidence collection, but every current-run container must be explicitly removed before confirmed completion. Shared services/resources and every generated report remain intact.

The convention revision clarified agent authorization without adding a remote CI pipeline. Installation-scoped `CI=1` remains a package postinstall control, distinct from hook bypass authorization.

All 70 tasks across sections 1–13 are complete. The original 60 checked descriptions remain unchanged as historical evidence. Section 13 superseded attached-client/automatic-removal assumptions with verified native completion, complete post-exit snapshots, stricter native evidence and explicit removal. Fresh acceptance includes the complete 60-case suite with real Docker/PTY enabled plus the additional historical-schema-4 regression, totaling 61 distinct exercised tests; `verification.md` records the 16 real-native runs and cancellation/removal evidence. Archive readiness is restored; no historical report or prior acceptance claim was rewritten.

### Risks

- A local OpenSpec job has no Docker object to remove. Applying the previous universal `removed` pass rule would reject valid local work or fabricate cleanup. Validate each backend against its registered ID, require `not_applicable` only for OpenSpec, and preserve `removed` as mandatory for PHP success.
- Bulk validation reads main specs and active change deltas, including work in progress. Invalid deltas can reject an otherwise valid PHP run; unchecked active tasks are allowed. Do not add archived-task checks, require changes to be complete, filter by changed filenames, or auto-fix artifacts.
- Extending the all-job registry can accidentally include OpenSpec in Docker ownership/cleanup. Keep the full ordered seven-job registry distinct from the six PHP-container IDs and test local identity spoofing, cancellation, and overlapping runs.

- Renaming paths can disconnect a killed job from its coordinator or creation-request owner and leave containers behind. Update all readers/writers together, preserve atomic publication and ownership checks, and exercise interruptions during directory creation, receipt publication, native output, and finalization.
- Existing runs have the old layout. Apply the new layout only to newly allocated executions; do not migrate, rewrite, delete, or inspect historical runs for recovery.

- Concurrent pushes can repeat checks and compete for CPU, memory, and tool caches. Such concurrency is accepted; exclusive run directories and independent job results prevent report overwrites.
- SIGKILL or container loss can leave incomplete diagnostics/results. An unfinished execution is not reported as successful; no user-change restoration is involved.
- Local hooks and environment identifiers are contributor guardrails, not a security boundary. Git cannot prove which tag name was checked out when several tags resolve to the same commit.
- QA verifies the final checked-out state eligible for push, not every intermediate commit individually. Local commits receive no QA gate.
- Existing local env files are not updated by `tools/env`. Contributors must add the required dev marker and recreate dev to apply it; a missing or incorrect marker continues to reject invoked pushes.
- The npm command requires Node and its package files, already supplied by dev. Yarn/package metadata handles platform selection and package integrity; the installation no longer uses independent hardcoded GitHub asset checksums.
- Moving hook documentation can leave duplicate rules or stale references. Preserve general Git/environment/report ownership and update the operational index and OpenSpec context map together.
- An instruction to push or repair a failure can be misread as bypass authorization. Lead the rule with `Agents MUST NOT bypass`, require explicit human authorization for the specific operation, and apply it before and after failures.
- A terminal stdin forwarded through Lefthook can remain open after a job exits. Preserve mode selection before input forwarding and verify the exact direct command with a PTY. Container-state observation and log collection must remain cancellable without EOF, fixed completion sleeps, re-executing tools, or changing Composer scripts.
- Frontend hard-kill behavior or stopping only a Docker client can leave work or created containers behind. Supervise frontend lifetime and container creation/start/removal, verify complete absence within the shared deadline, and expose cleanup failures rather than claim success. SIGKILL and Docker/container loss remain outside catchable-signal guarantees.
- Six fresh containers add startup overhead. Reuse the existing PHP image and runtime context without builds, pulls, dependency installation, or service recreation during hooks; verify performance with native acceptance.
- Premature Docker-client completion can trigger report parsing and cleanup while native work is still running. Observe the verified container through start and terminal state, persist its genuine native outcome, collect non-follow log snapshots, and remove only after normal collection or an explicit failure/cancellation path. Disable automatic removal so exit state and logs survive long enough to inspect. Settle late creation and verify every owned ID/name/label; a client exit is never proof of native completion or container absence.
- An unreachable Docker daemon prevents confirmed removal. Record an unsuccessful cleanup outcome without extending the deadline, erasing evidence, or asserting that resources disappeared.

The completion/capture revision applies only to future executions. Keep grouped paths, summary schema 4, native formats, Composer/script arguments and scopes, seven-job scheduling, authorization, full retention, and final container-removal guarantees. Extend current-run container metadata with terminal-state and collection evidence and strengthen report validation. Preserve previous run bytes, including empty or incorrectly passed historical reports, without migration, recovery sweeps, automatic retries, success-only deletion, or pruning.

This revision refines the same seven-job pre-push/manual gate with daemon-observed native completion, complete snapshot collection, stricter evidence validation and explicit final container removal. The dev-local OpenSpec validator remains unchanged. Add no PHP image tooling, Composer script/dependency, persistent service, package API, installation-time hook or automatic report pruning. Old runs and historical verification remain untouched. OpenSpec structural checks still do not prove semantic correctness or implementation/spec correspondence.
